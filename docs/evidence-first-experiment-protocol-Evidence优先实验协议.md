## 1. 要改善的用户结果

用户已经能够可靠保存、读取和追加文本，但尚未证明“保存之后能更快理解并形成可控的长期知识成果”。当前实验要回答：

> 从一份精确来源出发，系统能否形成有证据、可修改且允许独立结束的策展地图；当用户选择继续时，能否在一个全新隔离 KB 中把同一地图转成获批、可验证、可恢复的可信成果，并清楚显示范围、权限、缺口、成本和失败？

当前活动范围验证四项假设：

1. **H1——来源与证据底座可行**：精确 Capture 版本、确定性分段、处理范围和 Evidence locator 能支撑深入策展，不需要先冻结通用 Task、Ledger 或 Graph 规范事实。
2. **H2——深入策展产生用户价值**：对一份真实中长篇高价值材料，有证据的概览、结构、主张、争议和缺口能降低用户形成整体理解与复核结果的负担。
3. **H3——权限分层与可信写入闭环可行**：目标归属、深度处理和精确可信写入可以分别授权；地图在 T1/T2 结束不会被误报为 T3，继续路径则能把获批字节可靠写入一个新 KB 并验证、重试或恢复。
4. **H4——先实验再冻结 schema 可行**：首轮能以最小临时记录和受限业务事实完成复现；只有真实运行暴露出必须稳定保存的身份或状态后，才讨论正式 Task、Ledger、Evidence、Graph 或 RAG 持久化契约。

来源身份、分段、范围和证据回读不得要求云账号或外部服务。深入策展可以在另行确认后使用可替换模型处理器，但必须记录模型、调用、token、成本和网络依赖；模型不是 Capture、证据定位、原文回读、精确批准或受限执行的规范真源。

本轮不尝试证明 KnowledgeFlow 在任意领域、任意规模或任意问题上都准确，也不把一次 dogfood 演示升级为产品有效性声明。

## 4. 对照路径与运行顺序

### 4.1 `B0-C`：深入策展人工基线

用户以惯常阅读和笔记方式，从 `E0-C` 形成概览、结构、主张、争议和缺口。记录开始时间、首次有用结果时间、实际阅读范围、导航/查找次数、人工编辑或判断时间、最终成果和放弃原因。`E0-F` 只提供机械操作摩擦基线，不能用于宣称普遍效率提升。

#### 4.1.1 人工基线的实际操作

基线方法在协议评审时确定；实际用时和结果在 `C1` 语义对照前测量，不要求先为 `B1-C` 人工读完整份长文。

1. **长文**：使用惯常编辑器、浏览、查找和笔记方式，按 `C-T1`–`C-T4` 形成第一份自己认为能用的阅读笔记或结构；记录实际读过的范围、首份可用结果及尚未弄清的内容。不强制先读完 24,525 行，也不把未读完视为用户失误。
2. **记录方式**：由实施者准备并记录“任务、输入范围、开始/首个有用结果/结束时间、操作次数、成果、未读/未决、答案暴露与备注”，用户只需正常使用并指出什么时候结果已经有用；此记录是实验记录，不新增产品表单或持久化契约。
3. **比较限制**：记录是否先看过第 3 节候选、旧总结或系统结果。可行时由独立核查者先确认候选，用户在系统结果展示前做基线；若已经暴露，不补造一份“无提示”基线。处理范围不同只比较实际范围和首次有用结果，不能据此宣称完整任务速度提升。

`E0-L/E0-R` 的人工整理与文件查找基线保留到对应后续协议启用时再测，不在当前先做无用功。

### 4.2 `B1-C`：来源与证据底座

深入策展的第一个实现切片先闭合：

```text
精确 Capture 版本
  → 可复现的确定性 Segment
  → 处理范围、重叠和缺口记录
  → Evidence locator
  → 打开并回读对应版本的原文位置
```

`B1-C` 还须验证本地文件字节身份与实验 Capture Payload 的映射。它不做通用搜索 UI、模型摘要、聚类、embedding、图谱或可信写入。Segment 与范围记录的字段名、物理格式和保留方式仍是实验观察语义，可以在实验后废弃。

### 4.3 `C1`：目标判断、`raw/` 归档与策展地图

在 `B1-C` 上运行 `C-T1`–`C-T5`。当前主验收选择一个全新隔离 KB：先展示目标建议并取得新建/位置授权，运行获批后的 SOP-000A，机械归档精确来源到该 KB `raw/` 并验证映射，再生成正式地图。另以受控场景验证“不选 KB、只生成地图”不会触发建库或 `raw/` 写入。允许使用可替换模型处理器，但必须能关闭并记录完整调用事实。实验输出至少显示：

- 材料范围和未处理范围；
- 概览、结构、概念、主张、争议、限制和缺口；
- 每项对应的精确来源版本和 Evidence locator；
- 哪些内容是原文事实、模型归纳、用户修改或仍不确定；
- 用户接受、修改、删除和补充了什么。

`C1` 的地图可以保存来源绑定、范围和缺口后成功结束；这仍不是可信 Wiki 页面。正式运行前必须先完成入口和 SOP-000A/001 的契约批准，本节不允许用实验说明替代 SOP。

### 4.4 `C2`：精确方案、批准与单一新 KB 写入

从用户已复核的地图生成一个目标 KB 的候选最终正文、结构、导航、链接和精确 diff。用户批准完整待执行对象后，执行阶段不得重新作语义决定；新 provisional KB 的激活与首批可信写入处于同一可恢复业务边界，完成回读验证、检查点、幂等与报告后才能宣称成功。失败时保持或恢复到可证明的安全状态，不触碰 Pilot Store 或既有 active KB。

### 4.5 `C3`：端到端与命名验收

分别完成一次地图终点和一次可信写入终点，核对来源、三类权限、用户决定、批准对象、实际字节和报告。未命名新 KB 使用冲突安全的 `YYYY-MM-DD-NN`；首批入库后 Agent 给出一至三个显示名建议，用户决定后只改变显示名与 README，`kb_id` 和物理目录保持不变。

### 4.6 `L1/R1/R2`：后置线路

低摩擦批量整理、本地精确/关键词检索，以及可能的 embedding、重排序或模型问答均不在当前运行顺序内。它们的材料、问题和候选指标继续保留，待深入策展完整链通过后分别形成活动协议；不得为了复用共同底座而提前实现搜索 UI、调度器、RAG 或永久后台处理。

模型与数值预算属于 `C1` 的运行配置，不是 `B1-C` 的实现前置。本批没有调用新处理器，不把语义运行成本填成 0 或凭字节数估算 token。需要模型时，运行前提出可审核的处理器/模型、输入切分、每次与总输入/输出 token 上限、总调用次数、费用上限、网络范围和达到上限后的停点；按实际 tokenizer/服务计费口径测量，范围不能在预算耗尽时静默缩小。预算不允许全文时必须在开始前缩小并显式声明范围，或把未处理范围留为缺口，不将局部结果算作全文价值验证。

当前深入策展语义路径先做一次测量运行；失败后至多提出一次有界改进并保留前后结果，额外探索单列。长文处理不得用第 3.2.1 节的候选答案喂给待评估处理器，再把对候选的复述当成成功。

## 5. 深入策展活动链的最小实验约束

### 5.1 确定性分段

本协议不预先选择按标题、段落、字符窗口还是混合分段，但后续实现必须满足：

1. 同一来源版本、同一分段配置运行两次，得到相同的有序 Segment 身份、范围和内容摘要；
2. 每个 Segment 都能回到一个精确 Capture 版本和明确原文范围；
3. 整个声明处理范围可机械记账，不得静默丢弃空行、标题、表格或超长段落；
4. 若使用重叠窗口，必须在结果中记录重叠，不能把重复字节误算成额外覆盖；
5. Segment 和其他派生物删除后能够从 Capture 真源重建。

具体算法、阈值和跨版本稳定策略留给后续实现批次提出并用本协议验证；本协议不把实验选择升级为长期产品契约。

### 5.2 处理范围与 Evidence locator

每次运行必须登记输入清单、声明处理范围、实际完成范围、跳过/失败范围、重叠和生成物。任何策展结论、整理建议或检索候选都必须通过 locator 回到精确 Capture 版本和明确原文范围；只保存短片段不能替代原文回读。

### 5.3 本地检索（后置规则保留）

未来启用本地检索线路时必须：

- 本地、离线、无需账号和外部服务；
- 同一输入、查询和配置产生稳定排序，平分结果有明确确定性 tie-break；
- 同时保留精确短语和普通关键词路径，记录查询规范化；
- 不把材料标题、gold evidence 或问题 ID 硬编码成答案；
- 找不到支持证据时允许明确返回“未确认”，不得为了填满结果虚构结论。

### 5.4 实验性 Evidence Bundle

一次查询或策展任务的实验性 Evidence Bundle 至少能表达“处理什么任务、用了哪些 Capture/版本/Segment、每条证据对应什么原文范围、结果如何由证据支持、还缺什么”。检索结果还应记录排序和匹配依据。它可以是临时内存对象或实验目录中的可删除记录，不得因此冻结正式持久化 schema。

### 5.5 深入策展

- 不把语言流畅、条目数量或章节覆盖率当作理解正确的证明；
- 原文事实、作者观点、模型归纳、用户修改和未知项必须可区分；
- 地图必须允许删除、改写和标记未确认，不要求用户接受预设结构；
- 任何摘要、主张、关系和争议都应绑定支持证据或明确标记为待核验；
- 地图输出只属于 T1/T2，可以作为成功任务终点，但不能直接变成可信页面或稳定结构；
- 用户选择继续时，地图先形成精确变更方案；只有绑定目标前置状态、方案版本和 diff 的批准才能进入受限执行。

### 5.6 目标、权限和可信写入

- 精确 Capture 来源先于任何分析；用户确认目标后才允许目标 KB `raw/` 归档；
- 路由/归档、深度处理和可信写入分别授权，记录不得用一个笼统“已确认”代替；
- 首个切片只允许一个全新隔离 KB，未命名时使用冲突安全的日期序号；
- 执行器只应用获批字节，不重新调用模型改写；批准后目标前置状态变化必须使旧批准失效；
- 激活、首批可信写入、验证、幂等与恢复的成功事实必须来自可核验事务记录；失败时不得把 provisional 或部分写入报告为 active/完成。

### 5.7 低摩擦批量整理（后置规则保留）

- 首轮由用户手动触发，只读取冻结样本，不把一次授权扩展成永久后台授权；
- 原始条目保持不变，分组、摘要、重复判断和整理动作都只是可撤销建议；
- 用户可以整体或逐项接受、修改、忽略或延期；
- 不确定分组必须保留不确定状态，不为追求整洁强制归类；
- 在真实降负得到证明前，不建设调度器、常驻进程或自动可信写入。

## 6. 测量项与记录口径

| `MET-05` | 支持正确性 | 人工判断证据是否真正支持邻接结论；仅主题相近不算支持 |
| `MET-06` | 策展理解收益 | 用户是否能从地图形成材料整体结构、关键主张、争议和缺口；记录接受、修改、删除和补充 |

| `MET-11` | 可见缺口 | 未覆盖范围、无答案、歧义、冲突、错误命中、跨 Segment 断裂和用户不理解项逐例记录 |
| `MET-12` | 模型和外部成本 | `B1-C` 必须为 0 次模型调用、0 token、0 外部服务；`C1` 如使用模型则逐次记录；`C2` 执行阶段不得重新调用模型作语义决定 |

## 7. 首轮继续/停止判据

以下是首轮继续判据，不是产品 SLA：

1. **机械门禁必须全部通过**：输入身份一致；两次分段一致；声明范围没有静默缺口；所有 locator 都能回读精确版本和对应片段；没有读取清单外来源。机械门禁失败时不得用较好的语义结果抵消。
2. **首轮只建立深入策展语义基线**：不预设任意接受率。策展接受/修改/删除、地图终点是否有用、时间和人工负担必须如实记录，完成首轮后才能为下一轮冻结有依据的目标。`gold-hit@5` 与整理建议效用属于后置线路，不是当前通过项。
3. **地图价值与写入可靠性分别判断**：地图只有在整体理解和证据复核呈现净收益时继续；可信写入只有在三类权限、批准/执行一致性、验证、幂等和恢复全部可核对时通过。地图有价值不自动证明写入链，写入正确也不能证明地图有用。
4. **证据优先**：任何回答、地图条目或整理判断都必须绑定支持证据或明确标记为推断/未确认；出现错误引用时停用相应语义层并保留机械证据进行诊断。
5. **成本如实记录**：首次结果、人工操作、审核时间、模型和资源使用必须有实测值；未测不得写成“快速”“低成本”“智能”或“可扩展”。
6. **权限与执行必须精确**：未选择 KB 时不得建库或写 `raw/`；只允许深度处理时不得写 T3；批准对象与实际字节不一致、目标前置状态漂移或恢复事实不明时必须停止。

遇到以下任一情况必须停止当前路径，而不是自动增加向量数据库、模型或新 schema：

- 输入 blob 不匹配、误读 Pilot Store、读取清单外文件或发现敏感内容；
- 相同输入无法得到确定性 Segment 或定位结果；
- Evidence locator 不能回到精确 Capture 版本；
- 为运行 `B1-C` 必须登录、联网或把 GitHub/GBrain/模型作为前置；`C1` 使用模型时必须经过单独确认且能够完全关闭；
- 实现开始建立通用 Task/Ledger/Graph/RAG 持久化状态，超出临时实验所需；
- 一次有界改进后策展地图仍没有净用户收益；此时记录失败模式并重新评估，不自动进入 embedding、RAG、后台调度器或新 schema；
- 用户认为策展地图或证据导航增加了理解/审核负担，或无法解释系统为何产生结果；
- 未经用户确认目标就写入 KB `raw/`，未经深度处理授权调用语义处理器，或未经精确批准写入可信知识；
- 批准后目标文件漂移、执行字节超出 diff、同一批次重复产生副作用，或新 KB 状态无法证明为 provisional/active 中的哪一种。

数据泄露、越权写入、Capture 原件改变或定位错误属于立即停止并清理实验派生物的阻塞问题。

## 8. 数据隔离、复现与清理

1. 后续运行使用全新实验目录、全新实验 Store、一个全新隔离目标 KB 和显式实验配置；三者及当前 Pilot 的精确路径/身份必须在实现批次中先复核，不得复用或切换当前 Pilot 配置，也不得把实验 Store 冒充目标 KB。
2. 仓库机械夹具只读获取提交 `11b4722` 的指定 blob；`E0-C` 只读获取第 2.3 节绑定哈希的用户原件副本。当前不读取 `E0-L/E0-R`。实验不修改工作树材料、外部原件、Pilot Capture、活动配置、备份或恢复副本。
3. Segment、处理记录、索引、查询缓存和 Evidence Bundle 只能位于实验目录或内存，必须带运行 ID。策展地图位于任务工作区或未审核提案区；只有用户明确选择保留的地图和必要来源绑定可按批准范围长期保留，仍不得冒充可信知识。`C2` 只有精确方案中的获批字节可以进入本轮隔离目标 KB 的 T3，任何派生物都不能进入 Pilot Store、既有 active KB 或 GBrain。
4. 每次运行记录代码提交、材料快照、配置摘要、操作系统/Python 版本、可选模型事实、开始结束时间和清理结果；`C2/C3` 另记录目标 KB、方案、批准、事务和验证身份，使他人能够在相同依赖条件下重新运行。
5. 完成复核后删除可重建实验 Store 和未选择保留的派生数据，只长期保留不含完整正文的材料清单、运行参数、聚合指标、失败样例和必要短片段。隔离目标 KB 及用户选择保留的地图不自动删除；保留/清理决定必须显式记录。任何删除前先核对绝对目标确属本次实验范围，禁止宽路径或递归猜测。
6. 若需要保留失败现场，必须先说明原因、范围和保留期限；不得把“以后可能有用”当作无限期保留依据，也不得把失败现场登记成 active KB。

## 9. 预先登记的失败样例

首个实现与验收必须主动覆盖：

1. 中英文混合术语，如 `processing_mode`、`Evidence Bundle`、`operational-copy`；
2. 用户表达与原文用词不同，例如“恢复旧内容”与“以旧版正文追加为新版本”；
3. 标题、表格、对话标记或超长段落落在 Segment 边界；
4. 策展地图把作者引用、历史助手回答、系统推断或相邻段落误写成已核实事实；
5. 材料快照或哈希已经变化，仍必须停止，而不是静默改用当前文件；
6. 用户未确定目标，只选择地图终点，系统却自动建库、写 `raw/` 或准备 T3 变更；
7. 用户只确认目标/`raw/`，系统却把它解释成深度处理或可信写入授权；
8. 同一天两个新库竞争相同日期序号，或策展后显示名变化意外改变 `kb_id`/物理目录；
9. 地图或精确方案修改后仍沿用旧批准，或批准后目标前置状态发生变化仍继续写入；
10. 新 KB 激活、正文、导航或日志写入中断；重启后不得重复副作用、伪报成功或删除不明文件；
11. 用户选择已有 active KB 或多个目标时，首个切片必须明确报告后置/不支持，不得偷偷扩大范围。

原 `E0-L/E0-R` 的错误分组、近义检索、跨文档组合和无答案查询失败样例保留在第 3 节，等相应后置线路启用时再纳入该线路的强制验收。

所有失败保留原任务/查询、相关输出或前 5 个结果、人工判定和失败分类。不得删除失败样例后只展示成功截图。

## 10. `EVIDENCE-0` 完成条件

本门禁只有在以下内容经独立复核并进入获批协议提交后才完成：

- 活动输入 `E0-F/E0-C` 的身份、授权、体量和选择理由可复核；`E0-L/E0-R` 明确仅为后置登记，不存在会阻塞深入路径的 `TBD`；
- 机械夹具、深入策展任务及人工 gold/核查方法明确，待评估处理器与核查答案隔离；
- 入口/路由、SOP-000A/000B/001/002 已联合冻结两级保存、三类权限、地图终点、单目标首切片、日期序号、批准与恢复边界；
- `B0-C/B1-C/C1/C2/C3` 边界、16 项测量（其中 `MET-07/08` 后置）、无任意首轮语义阈值的继续/停止判据和失败样例明确；
- 数据隔离、复现、地图保留和清理规则不触碰 Pilot Store、备份、恢复副本或既有 active KB；
- 文档清楚声明外推限制、未授权编码和未冻结正式 schema；
- 文档护栏、链接检查和差异检查通过。

完成 `EVIDENCE-0` 只表示“知道要用什么材料、契约和方法验证深入策展”，不表示来源底座、地图、可信写入、低摩擦整理、检索、RAG 或产品价值已经实现或通过。

## 11. 后续实现边界（尚未授权）

协议与四份 SOP 契约批准后，按一个深入策展主门禁的小批次依次推进；具体编号和提交信息在授权时确认：

1. **来源与证据停点**：把 `E0-F/E0-C` 白名单装载到隔离实验 Store，完成文件字节与 Capture 映射、确定性分段、范围/缺口记账、locator、原文回读和双跑复现；不做语义处理或搜索 UI。
2. **目标与地图停点**：运行 `E0-C` 人工基线；闭合用户已明确/未明确目标入口、一个新 KB 初始化与 `raw/` 映射，并以可替换处理器形成有证据地图；同时证明不选 KB 的地图终点不会越权写入。
3. **方案与执行停点**：只对一个全新隔离 provisional KB 形成精确方案和批准记录，完成激活、首批可信写入、验证、幂等、故障恢复和报告；执行时不重新作语义决定。
4. **旅程停点**：分别验收地图终点和可信写入终点，验证日期序号、稳定 `kb_id`、显示名决定和用户对权限/结果的理解。

上述停点在产品最终运行时可以组合，但开发与验收保持小批次串行。向已有 active KB 写入、多 KB、低摩擦和多来源检索在该链通过后分别设计；只有真实结果证明某种稳定身份、调度状态或模型适配层确有必要，才提出相应长期契约。

只有历史版本入口缺失真实阻塞上述代表旅程时，才在停点前另行授权 P0C-UX0 界面实现；不能因为交互契约已经存在就默认插入 UI 编码。

首个 `B1-C` 批次的工作拆分建议：

1. 通过已有管理/捕获能力创建全新实验 Store，只复制 `E0-F/E0-C`，记录原文件身份与新实验 Capture 版本的对应；不修改 Capture v1 schema 或当前 Pilot 配置。
2. 在实验范围实现一个确定性文本分段方案，记录算法与配置；完整保存来源位置，单独记账空行、标题、表格、长段落及重叠。
3. 生成可删除的范围记录，明确覆盖、延期、失败或缺口；结构覆盖不能冒充语义处理完成。
4. 实现从精确实验 Capture/版本/范围定位并回读原文的最小入口；版本不存在或范围不合法时明确失败，不猜测“最新”或近似位置。
5. 对相同输入/配置运行两次，检查有序区段与内容摘要一致；删除派生物后重建并重新比较，原始输入保持不变。
6. 验收输入不匹配、错版本/越界定位、中英文与空行、边界内容、重叠记账和派生物重建；运行相应回归、文档护栏和差异检查，报告全部失败。此批不创建目标 KB，不增加模型、搜索页面、后台任务或通用知识图谱。

### 11.2 前端与这几步如何配合

低保真交互设计可以围绕“选来源 → 确认/跳过目标 → 看范围与地图 → 打开证据 → 修改/保留结果 → 在此结束或继续看精确变更 → 批准 → 看执行结果”准备；设计稿不构成界面实现或 schema 批准。`B1-C` 只需要可检查的命令输出/报告与原文入口。`C1` 确实暴露复核摩擦后，另行授权最小地图与证据界面；`C2/C3` 再加入批准对象和结果呈现。正式工作台与技术选型依据实际任务和所需最小接口收口，不把完整前端作为首轮机械实验前置。
