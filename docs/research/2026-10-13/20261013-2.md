## 一、修正后的完整流程

```text
外部文件
→ 先形成精确 Capture 来源版本
→ 判断用户是否已经明确目标 KB
```

### 情况一：用户已经了解材料并指定目标

```text
用户指定已有 KB 或要求新建 KB
→ Agent 读取精确来源，检查目标是否明显不合适
→ 给出“建议继续”或“建议调整”的理由
→ 用户确认最终目标
```

确认后：

- 已有 KB：检查其身份、状态和写入能力，不重复初始化。
- 新建 KB：确定父目录；有用户名称就采用，无名称则生成日期序号临时名称；运行 SOP-000A。

然后：

```text
将精确来源机械归档到目标 KB raw/
→ 校验正文哈希与 Capture 版本映射
→ SOP-001 生成策展地图
```

### 情况二：用户不了解材料或没有确定目标

```text
Agent 基于精确来源生成有限的“原料梗概”
→ 展示现有 KB 及适配理由
→ 建议：
   1. 放入已有 KB
   2. 新建 KB
   3. 暂不选择 KB，只生成策展地图
   4. 暂不深度处理
→ 用户确认
```

这里的“原料梗概”只用于帮助判断归属，不等于完整策展地图，也不能声称已经理解全文。

用户选择后：

- 选择已有 KB：归档到其 `raw/`；
- 选择新 KB：创建 provisional KB 后归档；
- 暂不选择 KB：来源仍保留在 Capture Store，地图保存在任务工作区或未审核提案区；
- 暂不处理：只保留来源版本。

然后才生成正式策展地图。

### 情况三：没有材料，提前建立知识库

继续保留之前确认的合法入口：

```text
用户要求提前建库
→ 确认父目录
→ 有明确名称则使用明确名称
→ 未指定名称则分配日期序号名称
→ SOP-000A 创建 provisional 空库
→ 验收并报告待用状态
→ 结束
```

此时没有材料，不生成策展地图，不创建 Schema，不激活可信检索。

## 二、策展地图之后的两个合法出口

策展地图完成后，用户可以选择：

### 出口 A：在地图处结束

```text
地图完成
→ 保存地图及来源绑定
→ 报告处理范围、缺口和未决项
→ 本次任务成功结束
```

它仍是工作成果，不是可信知识。以后可以重新选择目标 KB，生成新的变更方案。

### 出口 B：继续策展入库

```text
地图完成
→ 用户选择要保留、修改、拒绝和延期的候选
→ SOP-002 方案准备阶段生成最终正文与精确 diff
→ 用户批准精确变更
→ 受限执行
```

执行分支：

- 已有 active KB：只运行 SOP-002 执行阶段。
- 新 provisional KB：由 SOP-000B 与 SOP-002 在同一个可恢复业务批次中完成首批写入和激活。

因此：

> “地图可以结束”是用户任务允许停止；“完整链路验收必须实际完成一次入库”是项目开发必须证明写入能力。两者不冲突。

## 三、新知识库日期序号命名规则

你的命名要求合理，而且可以避免根据尚未理解的材料过早猜测名称。

### 1. 初始命名

用户没有明确指定名称时，统一使用：

```text
YYYY-MM-DD-NN
```

例如：

```text
2026-10-13-01
2026-10-13-02
```

规则应是：

- 日期使用本机配置时区的当前日期；
- 序号在同一知识库父目录、同一天内递增；
- 分配时加锁，防止两个进程取得相同序号；
- 名称只是临时显示名，不承担领域含义；
- `kb_id` 仍是独立、不可变的稳定身份。

用户明确给出名称时，例如“Agent 应用开发”，则采用用户名称，不强制改成日期序号。

### 2. 策展完成后的重命名

首批策展入库成功后，Agent 根据：

- 获批的知识内容；
- 实际领域边界；
- 首批页面；
- 排除范围；
- 与其他 KB 的区分；

给出一至三个名称建议和理由。

用户可以：

- 接受建议；
- 自己修改；
- 保留日期序号；
- 延后决定。

### 3. 第一版只改显示名称

为了避免路径、链接和配置随名称变化而破坏，第一版建议：

- `kb_id` 永远不变；
- 物理目录继续使用稳定的日期序号；
- 只修改 `kb.yaml` 的 `display_name` 和 README 中的显示名称；
- 不自动重命名文件夹。

例如：

```text
物理目录：
kb/2026-10-13-01/

kb.yaml：
kb_id: kb_...
display_name: 大模型应用开发
```

如果以后确实需要让文件夹名也跟随显示名变化，应作为独立迁移操作，检查链接、配置和并发编辑后再执行。
