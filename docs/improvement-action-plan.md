## 一、执行原则

| 原则 | 说明 |
|------|------|
| 小步提交 | 每条任务一个 commit；消息格式沿用现有风格（如 `fix: lint.py Windows 编码与 BOM 兼容`） |
| 先修复后宣称 | 文档中的状态标记（✅ / P1 等）只在验收通过后更新 |
| 规范优先于实现 | 脚本与 SCHEMA/SOP 冲突时改脚本，不改规范——除非先论证规范本身是错的 |
| 每项有验收 | 无验收标准的任务不进清单；验收以可复现的命令/输出为准 |
| 不扩大战线 | 本清单只处理已确认的问题，不新增功能（MC-001、聚类等仍按 build-plan 排期） |

## 二、P0：开箱可用性与交付一致性

### P0-1 修复 scripts 的 Windows 编码与 BOM 问题

**问题（已实测复现）**：
1. 中文 Windows GBK 控制台下，`lint.py` / `link-validator.py` 报告中的 `☒`（U+2612）等符号触发 `UnicodeEncodeError: 'gbk' codec can't encode character`，程序崩溃。必须设 `PYTHONIOENCODING=utf-8` 才能运行。
2. 带 UTF-8 BOM 的 `.md` 文件（PowerShell `Set-Content -Encoding UTF8` 的默认产物、Windows 编辑器常见输出）中，`parse_frontmatter()` 因 `content.startswith("---")` 失败而把完整 frontmatter 误判为缺失，产生大量「缺少 title/type/tags」误报。

**步骤**：
1. 三个脚本的 CLI 入口处统一加 stdout 重配置（用 `try/except` 兼容旧版 Python）：
   ```python
   try:
       sys.stdout.reconfigure(encoding="utf-8", errors="replace")
   except (AttributeError, OSError):
       pass
   ```
2. 文件解析统一剥 BOM：读取后 `content = content.lstrip("\ufeff")`，或 `read_text(encoding="utf-8-sig")`。
3. 用「带 BOM 的文件 + 默认 GBK 控制台」各跑一遍回归（复现命令见附录）。

**涉及文件**：`scripts/lint.py`、`scripts/link-validator.py`、`scripts/index-generator.py`

**验收**：
- [x] 中文 Windows 默认控制台（不设 `PYTHONIOENCODING`）运行三个脚本均无 `UnicodeEncodeError`（2026-08-24 以 `PYTHONIOENCODING=gbk` 等效模拟默认 GBK 控制台的 stdout 编码，三脚本 exit=0、stderr 空；重配置在启动后生效，与控制台初始编码无关）
- [x] 对带 BOM 的页面文件，lint 不再误报 frontmatter 缺失（2026-08-24 实测：BOM 页面 0 错误，wikilink 正常解析）
- [x] `--json` 输出为合法 UTF-8 JSON（2026-08-24 实测：GBK 模拟下 `json.load` 与字节级 UTF-8 解码均通过）

### P0-2 补齐 lint.py 与 SOP-003 的检查项差距

**问题**：`lint.py` 文档字符串宣称「按 SOP-003 的 9 项检查规范逐项排查」，实际完整实现仅 3 项（断裂 wikilink / 孤页 / 页面行数），frontmatter 检查只查 title/type/tags 三个字段（部分实现），标签审计静默失效，另有 4 项缺失：检查 3（index 完整性）、检查 7（日志轮转）、检查 8（entity 孤立专项）、检查 9（图谱过滤规则）。内部编号与 SOP-003 错位，当前 entity 孤立被并入通用「孤页」提示，未单独归类。

已实现的检查中另有四类口径分歧（实测确认）：

- **标签审计（SOP-003 检查 5）静默失效**：`load_schema_tags()` 只解析反引号包裹的 `` `#标签` `` 格式，而 `SCHEMA-template.md` / `sop-v2-full.md` 中标签以第五章表格行注册（无 `#` 前缀）→ 解析结果恒为空集 → `check_tag_registry()` 因空集守卫直接跳过——**未注册标签不告警，已注册标签也不校验**，检查名存实亡。同时缺少 SOP-003 要求的「已注册但未使用」提醒
- **500 行 Error 阈值为脚本自创**：`LINE_LIMIT_ERROR = 500` 在 SOP-003 中不存在（规范仅 300 行警告一档）
- **孤页严重度错位**：SOP-003 检查 2 输出级别为 `[错误]`，脚本归为 Notice
- **行内代码排除缺失**：SOP-003 检查 1 要求同时排除行内代码（`` `...` ``）与代码块，`extract_wikilinks()` 只排除了代码块——行内 `` `[[x]]` `` 会被误判为真实链接

**步骤**：
1. 实现 4 项缺失检查：
   - index 完整性：`wiki/` 全量文件 vs `index.md` 条目双向对比（缺失条目 / 多余条目）
   - 日志轮转：`log.md` 超过 500 条时提示轮转（脚本只报告、不自动执行；自动修复职责留给执行 SOP-003 的 Agent，脚本标注「可由 SOP-003 自动修复」）
   - entity 孤立：`wiki/entities/` 下无 concept 入链的页面单独归为 Error
   - 图谱过滤：`.obsidian/graph.json` 存在性 + `search` 字段含 `-path:schema`（SOP-003 检查 9 为可自动修复项，脚本先报告，标注「可由 SOP-003 自动修复」）
2. 修复标签审计（模板与解析器**同步双改**，避免格式各行其是）：
   - 先标准化注册格式：`templates/SCHEMA-template.md` 与 `sop-v2-full.md` 内嵌模板的第五章，所有注册标签（主题标签 + 性质标签）统一用反引号包裹（`` `标签名` ``，不带 `#`）
   - 再修 `load_schema_tags()`：解析第五章范围内的反引号包裹 token（向后兼容 `` `#标签` `` 旧格式）；实现「已注册但未使用」提醒（SOP-003 检查 5 的另一半）
3. 消除阈值与严重度分歧（按「规范优先于实现」原则逐条决策）：
   - 500 行 Error 阈值：写入 SOP-003（两档阈值），或从脚本删除——二选一，结论记录于 CHANGELOG（建议保留两档并写入 SOP-003：300 警告 / 500 必须拆分，对规范是净改进）
   - 孤页：脚本从 Notice 升为 Error，与 SOP-003 检查 2 对齐
4. 文档字符串的检查清单与 `docs/sop-v2-full.md` SOP-003 章节逐项对齐（编号、严重度分级）；`link-validator.py` 文档字符串中「lint.py 做全量 9 项检查」的过期交叉引用一并修正
5. 补齐检查项 1 的行内代码排除：`` `...` `` 包裹的 `[[x]]` 不视为 wikilink（SOP-003 要求代码块与行内代码同时排除）
6. `--json` 输出同步扩展新检查项字段

**验收**：
- [x] 构造测试 KB（index 缺失条目、entity 孤立、graph.json 缺失、log.md >500 条）四类问题均能检出（2026-08-24 实测：全缺陷 KB 检出 5 错误/14 警告/2 提示；graph.json 两种缺失形态——search 为空 [错误]、文件不存在 [警告]——均覆盖）
